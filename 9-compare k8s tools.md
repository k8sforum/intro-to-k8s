
# Tools

Local Kubernetes tools for development and learning. All run a real Kubernetes cluster on your machine — they differ in how they do it and what trade-offs they make.

## Comparison

| | minikube | kind | k3d | microk8s | Talos Linux |
|---|---|---|---|---|---|
| **Runs via** | VM or Docker | Docker containers | Docker containers (k3s) | Snap package (bare metal) | Bare metal, VMs, cloud, or Docker |
| **Multi-node** | Limited (1 control plane + workers) | Yes | Yes | Yes | Yes |
| **Speed to start** | Slow (VM boot) | Fast | Very fast | Fast | Slow (OS boot / image flash) |
| **Resource usage** | High (VM overhead) | Medium | Low (k3s is lightweight) | Low | Very low (immutable minimal OS) |
| **Kubernetes dist** | Upstream K8s | Upstream K8s | k3s (lightweight K8s) | Upstream K8s | Upstream K8s |
| **Best for** | Learning, full K8s feature parity | CI pipelines, multi-node testing | Local dev, fast iteration | Linux users, IoT/edge | Production, security-hardened clusters |
| **Platform support** | Mac, Windows, Linux | Mac, Windows, Linux | Mac, Windows, Linux | Linux native (VM on Mac/Win) | Linux (bare metal / VMs / cloud) |

## minikube
- The most beginner-friendly option — has a dashboard, addons system, and good documentation
- Spins up a VM (or Docker container) with a full single-node cluster
- Slower to start than the others due to VM overhead when not using the Docker driver
- Addons make it easy to enable ingress, metrics-server, registry, etc. with one command
- **Use when:** learning Kubernetes for the first time or needing full upstream K8s feature parity locally

## kind (Kubernetes IN Docker)
- Runs each K8s node as a Docker container — no VM required
- Originally built for testing Kubernetes itself; widely used in CI/CD pipelines
- Supports multi-node clusters (multiple control planes + workers) defined in a config file
- No built-in dashboard or addon system — more manual setup required
- **Use when:** writing CI pipelines that need a real cluster, or testing multi-node behaviour

## k3d
- Wraps **k3s** (Rancher's lightweight Kubernetes distro) inside Docker containers
- Fastest startup of the four — clusters spin up in seconds
- k3s omits some rarely-used K8s features (e.g. cloud-provider integrations) to stay lean
- Great `k3d` CLI for creating, deleting, and managing multiple clusters quickly
- **Use when:** local development where fast iteration matters and you don't need every upstream K8s feature

## microk8s
- Installed as a snap package directly on Linux — runs on bare metal, not inside Docker or a VM
- Lowest overhead on Linux; on Mac/Windows it still needs a VM (via Multipass), losing the advantage
- Has a rich addon system (`microk8s enable ingress`, `dns`, `registry`, `prometheus`, etc.)
- Used in production on edge/IoT devices (Raspberry Pi, etc.) — not just a dev tool
- **Use when:** you are on Linux and want the closest to a real cluster feel, or targeting edge deployments

## Talos Linux
[Talos](https://www.talos.dev/) is a purpose-built, immutable Linux OS designed exclusively for running Kubernetes. There is no shell, no SSH, no package manager — the entire OS is managed through a gRPC API using the `talosctl` CLI. This makes it one of the most secure and operationally consistent ways to run Kubernetes.

- **Immutable and minimal** — the root filesystem is read-only; only ~12 system processes run on the OS. Attack surface is dramatically smaller than a general-purpose Linux distro
- **API-driven** — all cluster operations (upgrades, config changes, node resets) go through `talosctl` or the Talos API. No imperative SSH access means no configuration drift
- **Declarative config** — nodes are configured via a single YAML machine config file generated by `talosctl gen config`. The same file can be used to reproduce a node exactly
- **Upgrades are atomic** — OS upgrades happen by swapping the entire OS image (A/B partition scheme), not by patching packages. If the new image fails health checks, it rolls back automatically
- **Runs anywhere** — bare metal, VMware, Hyper-V, AWS, GCP, Azure, Hetzner, Raspberry Pi, and locally via Docker (using `QEMU` or `talosctl cluster create` with Docker driver)
- **Local dev with Docker** — `talosctl cluster create` spins up a multi-node Talos cluster entirely in Docker containers, similar to kind but running the real Talos OS
- **Production-grade** — used in real production clusters, not just as a learning tool. Sidero Labs (the company behind Talos) also makes Omni, a managed control plane for fleets of Talos clusters
- **Limitation:** the no-shell design means debugging requires `talosctl dmesg`, `talosctl logs`, and `kubectl exec` rather than `ssh + journalctl`. The learning curve is steeper than the other local tools
- **Use when:** building a production or production-like cluster where security, reproducibility, and auditability matter. Also useful for learning how a properly hardened K8s OS works

### Key CLI commands
```bash
# Generate cluster config (outputs controlplane.yaml, worker.yaml, talosconfig)
talosctl gen config <cluster-name> https://<control-plane-ip>:6443

# Apply config to a node (during initial boot)
talosctl apply-config --insecure --nodes <node-ip> --file controlplane.yaml

# Bootstrap etcd on the first control plane node (run once)
talosctl bootstrap --nodes <control-plane-ip>

# Get the kubeconfig
talosctl kubeconfig --nodes <control-plane-ip>

# Spin up a local multi-node cluster in Docker
talosctl cluster create --workers 2

# Upgrade a node's OS image
talosctl upgrade --nodes <node-ip> --image ghcr.io/siderolabs/installer:<version>

# Stream logs from a service (e.g. kubelet)
talosctl logs kubelet --nodes <node-ip>
```
